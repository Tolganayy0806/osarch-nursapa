## Root cause
`/usr/local/bin/nightly-report.sh` contains Windows CRLF (`\r\n`, shown as `^M$`) line endings on every line—including the shebang line `#!/bin/bash\r\n`—causing `execve`/systemd to look for an interpreter path with a trailing carriage return (`/bin/bash\r`) and fail with `No such file or directory` (`status=203/EXEC`) whenever `nightly-report.service` runs (`17-cat-A-nightly-report-sh.txt`, `18-head-1-od-c.txt`, `07-systemctl-status-nightly-report.txt`).

## Fix
1. `sudo sed -i 's/\r$//' /usr/local/bin/nightly-report.sh`
2. `sudo chmod 755 /usr/local/bin/nightly-report.sh`
3. `sudo systemctl reset-failed nightly-report.service && sudo systemctl start nightly-report.service`

- **Expected output:** First line ends with `\n` and no `\r`, `nightly-report.service` finishes cleanly (`inactive (dead)` after `Type=oneshot` run or `active`), `/var/log/nightly-report.log` gets new timestamped entries every 2 minutes, and after `reboot` `nightly-report.timer` is `active` and continues appending new entries to `/var/log/nightly-report.log`.
